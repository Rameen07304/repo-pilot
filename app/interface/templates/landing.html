How it works

  1. 01

    Give it a repository

    Paste any public GitHub URL. The whole repository arrives in a single archive download, so a large codebase costs the same three requests as a small one.

  2. 02

    It parses the structure

    Every file is read with tree-sitter and every import is resolved to the file it actually points at, across nine languages. Nothing here is inferred by a model.

  3. 03

    Ask it anything

    Answers arrive with file and line citations you can open. Follow up with "it" and "that", and pick whether the explanation is written for a new developer, a senior engineer, a product manager, or someone hunting for ideas.

Real output, not a mockup

This is an architecture diagram Repo Pilot produced from an actual repository, exported from the app and dropped straight onto this page.

The structure is parsed, not guessed.

Most tools hand a codebase to a language model and print whatever it says back. A model asked to describe an architecture will invent dependencies that look plausible and are not there.

Here the graph comes from tree-sitter and the repository's own imports. The model is given what was found and asked to explain it. It cannot add an edge to the diagram, and it cannot produce a citation: every file and line reference is taken from retrieval and checked against the real file list before it reaches you.

Five ways in

  • Learn this codebase

    Ranks every file by how much the rest of the repository leans on it, then lays out what to read first and why. For the moment you have cloned something and have no idea where to start.

  • Ask a question

    Answers carry file and line citations you can open. Ask follow-ups with "it" and "that"; pick whether the answer is written for a new developer, a senior engineer, a product manager, or someone hunting for ideas.

  • Deep investigation

    For questions one search cannot answer. It runs several rounds, deciding what to look for next from what it just found, and shows you the trail as it goes.

  • Architecture diagram

    The import graph as a folder tree. Click any file to read its source, ask about it, or see what would break if you changed it.

  • Code health

    Circular imports, modules everything depends on, code no test covers. Computed from the parsed structure with no model involved, so it is instant and identical every run. Downloadable as a report.

How it behaves

Three requests per repository
The whole repository arrives in one archive download, whatever its size, so ingestion does not exhaust an API budget.
Nine languages in the graph
Python, JavaScript, TypeScript, Dart, Go, Rust, Ruby, Java and PHP, including Vue and Svelte single-file components. Each import is resolved to the file it actually points at.
Embeddings stay on the machine
Code is embedded locally. Only the question and the retrieved snippets are ever sent to a model.
Nothing half-indexed is kept
If a file cannot be fetched, the result is reported as incomplete and never cached as though it were whole.
