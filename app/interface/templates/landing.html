the difference

The parser decides what exists. The model only explains it.

Most tools hand a codebase to a language model and print whatever it says back. A model asked to describe an architecture will invent dependencies that look plausible and are not there.

Here the graph comes from tree‑sitter and the repository's own imports. The model is given what was found and asked to explain it. It cannot add an edge to the diagram, and it cannot produce a citation: every file and line reference is taken from retrieval and checked against the real file list before it reaches you.

under the hood

The numbers, all of them true.

Four requests per repository
One to check the repository is public, one for the commit, one for the file tree, and one archive download that carries the whole repository whatever its size. Ingestion never exhausts an API budget.
Nine languages, parsed not scanned
Python, JavaScript, TypeScript, Dart, Go, Rust, Ruby, Java and PHP all get a real grammar: every function, class and method is extracted, not just the imports. Vue and Svelte single‑file components are read for their imports, since the file is a template rather than a script. Each import is resolved to the file it actually points at.
Embeddings stay on the machine
Code is embedded locally. Only the question and the retrieved snippets are ever sent to a model.
Nothing half‑indexed is kept
If a file cannot be fetched, the result is reported as incomplete and never cached as though it were whole.
